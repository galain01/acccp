## shadcn / UI structure

- UI primitives live in `components/ui/`. Add new ones via `npx shadcn@latest add <name>`.
- Primitives use `@base-ui/react`, `cn()` from `lib/utils.ts`, semantic design tokens from `app/globals.css`, and Lucide icons.
- App composites (`application-usage`, `dashboard-sidebar`, `document-workspace`, etc.) import sibling UI with `./`; pages and layouts use `@/components/ui/...`.
- Config: `components.json` — style `base-rhea`, CSS variables, Lucide icon library.
- Theme: forced light mode in `app/layout.tsx` (`ThemeProvider forcedTheme="light"`) to match Canvas.

## Data layer

- **Postgres via Supabase**, accessed with **Drizzle ORM** (`drizzle-orm/postgres-js`). Client setup: `lib/db.ts` (uses `prepare: false`, required by Supabase's transaction-mode pooler; caches the client on `globalThis` in dev to survive HMR). Schema: `lib/db/schema.ts`; relations: `lib/db/relations.ts`.
- `lib/db/connection-options.ts` accepts optional `DATABASE_SSL_CA` (public PEM certificate, actual or escaped newlines). When set, the app uses `ssl: { ca, rejectUnauthorized: true }`, overriding URL SSL options and verifying the certificate/hostname. Without it, URL/driver TLS behavior is preserved; Postgres.js defaults to no TLS. Configure the hosted app with its Supabase CA and `sslmode=verify-full`. Restart/redeploy after changes. Drizzle CLI uses a separate driver and does not read this app-only variable; supply the public CA through Node's `NODE_EXTRA_CA_CERTS` at process startup for CLI migrations.
- Core tables: `users`, `auth_sessions`, `accounts`, `verifications` (better-auth's tables, mapped — see below), `sessions`, `documents`, `conversion_jobs`, `artifacts`, `validation_findings`, `job_events`, `model_calls`. Plus several `pgView`s for admin summaries (`admin_finding_summary`, `admin_retention_summary`, `admin_job_status_summary`, `admin_daily_job_summary`, `user_session_file_overview`).
- All tables have RLS enabled (`.enableRLS()`); app code goes through the Drizzle client with the app's own authorization checks (`verifyRoleOrRedirect` / `verifyRoleOrUnauthorized` in `lib/auth.ts`), not per-user Postgres roles.
- **Sessions and documents are persisted** (no longer in-memory demo state). `contexts/session-context.tsx` (`SessionProvider`) treats the `sessions` prop from the dashboard layout as server state; every mutation (`createSession`, `renameSession`, `archiveSession` in `lib/actions/sessions.ts`) goes through a server action that revalidates the layout. Document actions live in `lib/actions/documents.ts` (`listDocuments`, `getDocumentHtml` — output HTML lives in storage and is fetched on demand; `deleteDocument` — commits an owned tombstone, then attempts retryable file and database deletion).
- **Document retention is 14 elapsed days from original `documents.created_at`**, including reconversions, archived sessions and failed uploads. `lib/document-retention.ts` shares a PostgreSQL document row lock between conversion storage/metadata writes, HTML retrieval and purge; keep native rendering/model calls outside that transaction. Check the DB clock after acquiring the lock and after the callback. Do not write document blobs/metadata outside `withRetainedDocument` or extend expiry on reconversion. Purge removes canonical and all artifact-linked storage keys before cascading document deletion; failures preserve discovery records. See `docs/document-retention.md` for migration `0008`, daily cleanup timing, dry-run and rollout. Application expiry works independently of cron enablement; the separate test app must use isolated data or the same retention-aware code before enabling production cleanup.
- `lib/db/errors.ts` (`isUniqueViolation`) detects Postgres `23505` by walking the error `cause` chain — Drizzle wraps driver errors, so `error.code` is never on the top-level error.
- Migrations: `npm run db:generate` / `db:migrate` / `db:push` / `db:studio` (drizzle-kit).

## Auth

- **better-auth**, configured in `lib/auth.ts`, using the **Drizzle adapter** against the same Postgres schema (`users`/`authSessions`/`accounts`/`verifications` tables above; `generateId: false` since Postgres assigns UUIDs). Client-side helpers: `lib/auth-client.ts`. Route handler: `app/api/auth/[...all]/route.ts`.
- Sign-in is **email OTP only** (`emailAndPassword` disabled), via the `emailOTP` plugin. A `before` hook on `/sign-in/email-otp` and `/email-otp/send-verification-otp` rejects any email that doesn't match `OSU_EMAIL_REGEX` (`@...osu.edu`, including subdomains like `buckeyemail.osu.edu`) — this is what scopes sign-in to OSU accounts without needing Microsoft Entra tenant access.
- OTP delivery: `lib/email.ts` (`sendOtpEmail`). `EMAIL_PROVIDER=console` (default) logs the OTP for local dev only; production and Vercel previews reject console delivery. Set to `resend` (with `RESEND_API_KEY` / `EMAIL_FROM`) for deployed sign-in. Raw provider errors are never returned or logged.
- Users have a `role` field (`pending | instructor | admin`, default `pending`). Gate server components/actions with `verifyRoleOrRedirect(permitted)` and API routes with `verifyRoleOrUnauthorized(permitted)`, both in `lib/auth.ts`.

## Storage (Supabase Storage)

- `lib/storage.ts` is a server-only Supabase Storage client (bucket `documents`), built with the **service role key** — necessary because auth is better-auth, not Supabase Auth, so requests carry no Supabase JWT and an anon-key client would be treated as anonymous. Never import it from a client component. Ownership is enforced in app code before every call, same as the DB.
- Objects are keyed `sourceDocxKey(sessionId, documentId)` → `{sessionId}/{documentId}/source.docx` (Word original), `sourcePdfKey(...)` → `{sessionId}/{documentId}/source.pdf` (uploaded PDF or rendered Word), and `htmlOutputKey(...)` → `{sessionId}/{documentId}/output.html`, grouped by session so a session's blobs can be swept together. Uploads use `upsert: true`; reconversion preserves the original source and replaces generated output. Downloads for end users go through short-lived (`createSignedUrl`, default 5 min) signed URLs since the bucket is private.
- Required env vars: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`.

## Document conversion pipeline (LiteLLM)

- **Output destinations are explicit** in `lib/output-formats.ts`: PDF/DOCX input supports `canvas_html`; standard PPTX supports `accessible_pptx`. No other combination is implemented. The selector applies to newly added files; saved rows retain `outputTarget` and `jobId`. API requests default to Canvas only for backward compatibility and reject mismatched targets before reading sources or rendering. Preserve the shared all-call cost and original 14-day expiry rules.
- **Native PowerPoint remediation** lives in `lib/powerpoint-convert.ts`, with dedicated prompts in `lib/prompts/powerpoint-accessibility.ts`. Inspect the real ZIP/XML package through `lib/pptx-package.ts`; use the existing configured Gotenberg worker via `lib/powerpoint-rendering.ts` only for temporary PDF previews, followed by the existing PDF page renderer. The model sees the object inventory and slide images/PDF, including hidden slides but excluding speaker-note pages. Output comes from patching the original editable PPTX package, never from reconstructing Canvas HTML. No new external document service is introduced. See `docs/powerpoint-accessibility.md`.
- The PowerPoint repair model returns bounded operations on exact slide/object IDs; code validates full slide coverage and rejects arbitrary replacement XML. In the revision workflow, the model may replace authored descriptions, set exact passages' language, improve hyperlink labels without changing destinations, adjust text size/color and object bounds, and change reading order with visible-output audit. Preserve untouched package parts, original facts/data, slide/object identities, grouping, notes, media and relationships. Native decorative state changes require an explicit supported operation and may never hide a functional image. `lib/pptx-description-slides.ts` appends editable description slides for supported complex images; original slide identities/order remain intact. Added slides and their source description form one reversible change, and selected replay recalculates slide references. Shared repair/audit prompts follow the W3C image decision tree: reachable native text can make an image redundant; pixel text alone cannot. All appended slides must be rendered and audited. `splitTableCaption` separates one full-width caption from real labels in a simple **two-column** table while preserving all source data. Never mark a spanning caption as column headers just to satisfy a checker. Grouped/animated/hidden edits and unsupported structures remain bounded by the engine. Run machine checks before model work and on each reopened output. All final slide images and inventories reach the independent audit; visible changes alone do not cause rollback. One focused audit repair pass may run, with all model calls counted. HTML audit auto-repair stays disabled.
- `lib/pptx-revisions.ts` derives before/after change records from the actual reopened output and stores a source hash plus bounded plan. Replay selected atomic changes from the immutable original; verify the saved bundle and selected IDs before editing. Review notes explain decisions/assumptions but never substitute for measured differences. The UI prioritizes assumptions, permits keep/restore and description edits, and distinguishes included changes from reviewed changes. Chosen exports run machine/render/audit checks again without reapplying declined changes. Machine defects and unavailable evidence cannot be dismissed by a semantic audit. Keep general native-PowerPoint-check guidance outside issue counts and never call output certified.
- Empty native placeholders are a deterministic cleanup before PowerPoint model interpretation. Remove only slide-local placeholders whose package structure proves they have no content or function; scan hidden slides as well. An empty text string alone is insufficient evidence. Preserve filled placeholders, dynamic fields, authored alternatives, interactions, visible styling and referenced/opaque structures, along with reusable masters/layouts. Every applied removal is a reversible `empty-placeholder` change. Reopening verifies the exact removed IDs and retained content. Stored reading-order plans include original IDs so selected replay can restore a placeholder without moving it above overlapping content; never silently reapply a declined removal. Rendered previews omit PowerPoint's empty editing prompts, so this requires package checks.
- `lib/powerpoint-review-storage.ts` authorizes owned, retained jobs and guards exports with a saved-review hash, attempt count and short database lease. Reserve nonavailable artifact rows before creating each immutable selected-output/review pair, so failed saves remain discoverable by purge; switch available pointers only after upload succeeds. Model/render work stays outside the document lock. Record export checks in model_calls before switching outputs, including calls from failed checks. Review JSON, previews, choices and event metadata expire with the original upload; downloaded files are unaffected. Never persist content in browser localStorage. `/api/powerpoint-review` has the same native renderer tracing as `/api/convert`.
- Migration **`0013_powerpoint_outputs`** adds `source_pptx`/`pptx_output` artifact types, non-null Canvas-default `output_target` and `profile_version`, the composite `(document_id, output_target)` unique constraint and PowerPoint failure categories. Keep the legacy document-only unique constraint in this release so old upserts work during rollout. Supported input/target pairs remain one-to-one. Remove that legacy constraint only in a later compatible release that enables multiple destinations for one source. Do not run migrations against a hosted database without the intended rollout authorization.
- PowerPoint storage keys are `sourcePptxKey(sessionId, documentId)` for the immutable original and `pptxOutputKey`/`outputReviewKey(sessionId, documentId, jobId)` for output and review JSON. Writes use the same retained-document lock as Canvas. Purge derives every job's canonical PPTX/review paths as well as every source/artifact path, covering failed metadata transactions. `getDocumentOutputDownload` authorizes ownership/target/retention and signs a correct attachment filename for at most 60 seconds, bounded by original expiry even after signing latency. `getDocumentHtml` remains Canvas-only. Change summaries are bounded job-event metadata and expire with document content; list retrieval does not download every result.
- Shared metrics count PDF pages for Canvas and slides (including hidden slides) for PowerPoint in `page_count`; label mixed values pages/slides. Conversion/audit/retry/failure costs remain included. Anonymous daily/model totals survive purge; output-specific historical aggregates are not implemented yet. Local evaluation can use `node --conditions=react-server --env-file=.env.local --env-file=.env.word-to-pdf --import tsx scripts/convert-powerpoint.ts input.pptx output-directory`; the CLI writes local results and does not save a hosted job. Test real PowerPoint opening/Accessibility Checker and representative screen-reader navigation before release, alongside package, route, UI, ownership, signed-download and retention suites.

- `lib/litellm.ts` is the shared LiteLLM client (see `docs/model-pricing.md`): `callLiteLLM()` posts to `${LITELLM_BASE_URL}/chat/completions`, and `fetchModelPricing()` reads `${LITELLM_BASE_URL}/model/info` (5-min in-memory cache) to price calls via `computeCallCostUsd()`. Required env vars: `LITELLM_BASE_URL`, `LITELLM_API_KEY`. The optional `LITELLM_MODEL` overrides `DEFAULT_LITELLM_MODEL` (`gpt-5.6-sol-2026-07-09`); unset or blank values use the default. The API key must authorize the selected proxy model. `scripts/quality-check.ts` uses this same configuration, with an optional `LITELLM_QUALITY_MODEL` override for its final reviewer.
- `lib/convert.ts` (`convertPdf()`) renders all PDF pages once through `lib/pdf-rendering.ts`, then sends the same original PDF and explicit high-detail page PNGs to both model stages via `lib/pdf-model-input.ts`. Rendering fails before model calls if any required page is unavailable. Source images permit 24 MP each, 32 MP per page's declared resource graph, and 480 MP across the document; output resolution is unchanged. Each Node process runs one renderer child with up to four FIFO waiters (30-second queue deadline, then 90-second rendering deadline); keep the slot until child closure. The child process is memory-only and receives fixed runtime environment values without app credentials; it is not an OS sandbox or a hard native-memory cap. Node 24 and traced PDF.js/native-canvas assets are required. See `docs/pdf-visual-audit.md` for limits and deployment checks.
- The audit receives heading occurrence IDs/text and HTML with heading ranks and converter comments withheld. `lib/html-headings.ts` uses parse5 source offsets; `lib/heading-review.ts` validates source-outline coverage and compares actual parent relationships. Page text can reject contradicted heading locations but does not prove semantic relationships. Incomplete evidence always retains a warning. Prompts live in `lib/prompts/pdf-accessibility.ts` and `lib/prompts/accessibility-audit.ts`; finding contracts are in `lib/accessibility-findings.ts`, and source-marker/duplicate handling in `lib/pdf-review-findings.ts`. Faculty see plain-language actions and locations; technical details are optional. Source-authored draft reminders are not audit tasks. Existing findings remain subject to ownership checks and 14-day deletion. PNGs, page text and source outlines are request-local only. See `docs/source-aware-audit.md`.
- `lib/pdf-image-alternatives.mjs` extracts bounded authored Figure alternatives in the same renderer child, with measured MCID regions when associations are reliable. Both model stages receive identical source JSON. Do not match figures by structure order or treat output `data-source-image-id` as proof of visual identity. Preserve non-empty descriptions verbatim; retain warnings for unavailable metadata or ambiguous matching. `lib/pdf-image-review.ts` independently flags lost/changed/reused descriptions. Raw descriptions and bounds remain request-local; descriptions in final HTML/findings follow document retention. The helper must be traced and explicitly readable by the child. See `docs/pdf-image-descriptions.md`.
- `lib/pdf-revisions.mjs` resolves current objects through the PDF's cross-reference tables/streams and revision chain before image preflight and authored-description inspection. Keep selection consistent with PDF.js; never use physical last-definition order or reject every repeated object ID. Original bytes remain unchanged. Trace the helper and grant the renderer read access; the build smoke test includes an appended save.
- `lib/pdf-render-warnings.mjs` permits only the exact single-string PDF.js TrueType undefined-hint-function warning with an index 0–65535. PDF.js 6.3.289 drops invalid hint instructions while this renderer draws glyph outlines (`disableFontFace: true`). All content/unknown warnings remain fatal. Reassess the exception if the library or font-rendering mode changes; trace the helper and include it in the child read permissions and build smoke test.
- `lib/prompts/canvas-compatibility.ts` embeds the same Canvas tag, attribute, inline CSS and destination rules in conversion and audit. Keep the narrower app subset distinct from Canvas's full allowlist. Do not recommend table-cell `headers` or `li value`, which are absent from the published attributes. Preserve expected image placeholders, source image IDs, neutral audit heading markers and escaped code examples. These are prompt rules, not a sanitizer; see `docs/canvas-html-compatibility.md` for the dated source and maintenance notes.
- `lib/word-to-pdf.ts` (`renderWordToPdf()`) sends one DOCX to the configured Gotenberg/LibreOffice worker before these PDF stages. It requires HTTPS and Basic authentication for hosted workers, allows HTTP loopback only in local development, refuses redirects, bounds rendering/download to 60 seconds, and validates/caps the returned PDF at 4 MiB. Worker errors return safe summaries. See [docs/word-to-pdf.md](docs/word-to-pdf.md) for the pinned local Compose service, outbound restrictions, and the database-free `npm run convert:document` CLI.
- Native deployment uses `vercel.json` Services (`web` Next.js + private `renderer` container); set the project's framework to Services. Only `web` receives public traffic. Its binding injects `GOTENBERG_URL`; do not manually configure the URL for this topology. Supply both renderer credentials and the existing app variables in each deployment environment. `services/renderer/start-renderer.sh` honors injected `PORT` (default 80), clears inherited app secrets before starting even `tini`, and fixes renderer controls including `LOG_LEVEL=error`. Hosted Gotenberg URL filtering is application-level; Vercel documents no equivalent to the local Compose worker's deny-all network egress. An external HTTPS worker remains possible with a normal Next.js deployment and explicit URL instead of the binding.
- Successful Word conversions include a persistent manual-review finding about omitted linked content and possible font/layout changes. Keep it in both the API and CLI output; renderer success does not prove fidelity to the original Word document.
- The stage-1 output is pretty-printed with **prettier** (`parser: "html"`) before validation/persistence; formatting failures fall back to the raw string rather than failing the conversion. `lib/canvas-html.ts` then compacts whitespace inside actual closing tags using parse5 source offsets, including on the formatting fallback path, so Canvas receives `</a>`/`</em>` instead of split closing tags. It preserves surrounding whitespace, attributes, comments and literal examples; it is not an HTML sanitizer or repair pass. The audit, persisted output, copy and download all use this normalized HTML. PDF image placeholders and source-review comments produce deterministic warnings in `errors[]` and the compatibility `extractionWarnings[]` field. Images are not extracted/uploaded; users re-add them in Canvas. Incomplete or non-HTML model output fails conversion rather than being saved as success.
- Audit responses are validated at runtime as an object containing `headingReview` and `findings`. Legacy arrays, malformed JSON, incomplete heading coverage, or invalid entries produce a manual-review warning. Valid findings, deterministic markup checks and model-call usage are retained; invalid evidence is never silently treated as a clean audit.
- `lib/conversion-status.ts` (`toConversionStatus`) maps DB `job_status` values onto the dashboard's simpler `ConversionStatus` (`idle | queued | processing | success | error`; `needs_review` counts as success, `expired`/`cancelled` as error, no job row = `idle`). UI-facing types (`UploadedDocument`, `Session`) live in `lib/types/document.ts`.
- `POST /api/convert` (`app/api/convert/route.ts`) verifies session ownership and, on reconversion, document ownership before accessing sources or rendering. DOCX rendering completes before new document persistence or model calls; rendering failures preserve a saved document's prior job. New document metadata (MIME, size, SHA-256) describes the original upload. Word uploads store both `source.docx` and the exact `source.pdf` passed to `convertPdf()`; direct PDF uploads bypass the renderer. Reconverting stored DOCX downloads and renders its original again without creating another document or overwriting that original. The prior stored PDF is replaced only after model conversion succeeds.
- After source storage succeeds, the route upserts a `conversion_jobs` row by document/target (one target per input in this release; reconversion increments `attempt_count`) and calls the destination engine **outside** any DB transaction. Canvas success uploads HTML and upserts `source_pdf`/`html_output` plus `source_docx` for Word; PowerPoint success saves its source/output/review artifacts. The success transaction marks the job `completed`, replaces `validation_findings`, logs a `job_events` row, and inserts `model_calls`. One available artifact per type is enforced by `uq_available_artifact_per_job_type`. A model conversion failure retains billable usage and records the failed job/event.
- Costs prefer the valid gateway response-cost header, then gateway metadata, then a dated and labeled published Sol estimate. Cache-read/write counts and long-context tiers affect estimates; source metadata survives in `model_calls`. Existing non-null historical costs are immutable.
- Per-call token usage/cost is captured as `ModelCallUsage[]` and persisted to `model_calls` (stage `convert`/`validate`), which backs the admin cost/token tracking metrics tab.
- `GET /api/admin/model-info` returns pricing for the currently configured model with its gateway/list-price source metadata (admin-only) — distinct from the historical per-call cost in `model_calls`, which is snapshotted at call time so past spend doesn't shift if LiteLLM's pricing changes later.

- PDF, DOCX and PPTX uploads share the existing 4 MiB limit and client/server rules in `lib/document-input.ts`. PDF requires its extension and `%PDF-` header; DOCX/PPTX require their extension and ZIP local-header signature. Word parsing is delegated to the renderer; PowerPoint also undergoes explicit bounded package validation. Legacy `.doc`/`.ppt` and macro-enabled `.docm`/`.pptm` are unsupported. `app/api/convert/route.ts` retains Node runtime and its 300-second duration. Deletion cleans every canonical source path and discovered derivative.
- The prior `drizzle/0007_source_pdf.sql` migration must be applied; it adds `source_pdf` to `artifact_type` without changing existing artifacts. Word rendering needs no additional migration. If the private Supabase bucket restricts MIME types, allow `application/pdf` and `application/vnd.openxmlformats-officedocument.wordprocessingml.document`. Do not apply migrations to an unintended database.

## Admin surfaces

- Saved errors use the strict versioned `lib/job-diagnostics.ts` contract. Faculty messages are generated from categories; raw provider bodies, document text, exception messages, and arbitrary headers must not be persisted. `job_events.metadata.diagnostic` is admin-only and expires with its document. Admin recent-job details must match the current failed attempt and recheck retention. See `docs/saved-error-details.md`.
- Migration `0012_saved_error_details` adds `daily_failure_metrics` (UTC day/stage/code/count only). Each recorded failure increments it in the same transaction as its job event and available billable usage, using the same explicit timestamp. Word-rendering failures before job creation increment anonymous totals without creating empty documents or replacing prior jobs. These are attempt counts from this release onward, not latest-job status counts. Purge must not rearchive these totals. Apply the migration before deploying this code.

- Migration `0010_dashboard_job_metrics` adds nullable page counts and monotonic successful-processing durations, per-call pricing provenance/cache counters and unrestricted decimal cost, retained daily/model job token/page totals, exact duration-frequency counts, and nullable pricing coverage. See `docs/dashboard-metrics.md` for definitions and rollout. Job cohorts use original job creation dates; usage uses call dates. Retain these aggregates without instructor/document identifiers.
- `lib/admin-metrics-history.ts` reads selected-date daily/model/summary metrics in one SQL snapshot, including exact weighted medians; `lib/actions/metrics-history.ts` authorizes admins and validates UTC date ranges. The dashboard offers 30/90/365-day, all-time and custom views, charts and daily values. Every cost metric includes conversion, audit, retries and recorded billable failures. Average cost per job follows the selected original-job-creation cohort and includes only jobs with at least one call and complete recorded pricing; valid zero charges count, missing prices do not. Migration `0011_average_job_cost` preserves measured cost sums/counts and estimated-job counts after purge, without identifiers. Existing retained jobs without cost measurements stay excluded. Do not average daily means/medians or divide call-date usage by job-date cohorts for per-job averages.
- `lib/pdf-page-count.ts` counts the actual final PDF inside a time/input/heap-bounded worker. Parse failure is a null metric, not a conversion failure. The parser bundle is explicitly traced by `next.config.ts`; verify its worker path in the production build. Processing time begins before Word rendering and ends in the final success metadata update. Older partial timestamps are not substitutes.

- Migration `0009_retained_metrics` adds `retained_job_metrics` (UTC day/status/job count) and `retained_model_metrics` (UTC day/model/stage/call count/tokens/nullable cost). `archiveDocumentMetrics` runs inside the locked purge transaction after blob removal and before cascading document deletion, so rollback/retry cannot double-count. These aggregates deliberately retain no document/user/instructor identifiers, filenames, snippets or raw errors. Do not expire them with document content. Admin summary cards read a single SQL snapshot combining current records and retained totals; token/cost windows use UTC calendar days including today. Job success retains the latest job-per-document semantics, while usage counts every recorded model call. The detailed recent-job table remains limited to unexpired documents.

- `app/admin/page.tsx` + `components/ui/admin-metrics.tsx` is the admin dashboard: pending-user approval queue, job status summary, token/cost usage over a configurable day window, and a paginated recent-jobs table (filename, requester, status, model, tokens, cost).
- `lib/actions/admin-metrics.ts` (all admin-role-gated via `verifyRoleOrRedirect(["admin"])`): `getUserRoleCounts`, `getJobStatusSummary`, `getTokenUsage(days)`, `getCostSummary(days)`, `listRecentJobs(page, pageSize)`, `listPendingUsersPage(page, pageSize)`. Pure aggregation/pagination helpers live in `lib/metrics-math.ts` (unit-tested).
- `lib/actions/admin-users.ts`: `approveUser` (flips role `pending → instructor`) and `rejectUser` (hard-deletes the user row — no soft delete). New users default to role `pending` and land on `app/pending-approval/page.tsx` until approved; `app/unauthorized/page.tsx` handles role-mismatch redirects from `verifyRoleOrRedirect`.

## Route map

- `app/page.tsx` — sign-in (email OTP).
- `app/dashboard/layout.tsx` — redirects signed-out users to `/` and `pending` users to `/pending-approval`, loads sessions via `listSessionsEnsuringDefault()`, provides `SessionProvider`, and shows an **Admin** header button (link to `/admin`) for admins; `app/dashboard/page.tsx` and `app/dashboard/[id]/page.tsx` — session-scoped document workspace.
- `app/admin/page.tsx` — admin metrics/user-approval dashboard (role `admin`); tabbed (users / metrics), links back to `/dashboard`.
- `app/pending-approval/page.tsx` — held here until an admin approves (role `pending`).
- `app/unauthorized/page.tsx` — role-mismatch landing page.
- `app/not-found.tsx` — 404 page with a link back to sign-in.
- `app/api/auth/[...all]/route.ts` — better-auth catch-all handler.
- `app/api/convert/route.ts`, `app/api/admin/model-info/route.ts` — described above.
- `GET /api/cron/purge-documents` — authenticated daily retention sweep; counts-only response, 503 on failed/incomplete cleanup. Query `dryRun=true` never deletes data. Scheduled via top-level `vercel.json.crons` and routed to `web`.

## Gotchas

- Batch Convert selects only unlocked, supported documents with `idle` or `error` status. Successful documents require their explicit per-row Re-convert action, including after reload. Re-convert is disabled while locked or while any conversion is active. Preserve a failed response's saved document ID so retries reuse its source and job.
- The document `locked` flag is client-state only (`documents` has no locked column) — locking excludes a document from conversion, and resets on reload. Successful status still excludes it from batch Convert after the lock resets.
- Uploaded files are held in client memory (`UploadedDocument.file`) until first conversion persists them; a document row + storage upload only happens on convert, not on upload.
